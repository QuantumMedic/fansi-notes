# 03｜頁面規格、狀態與內容顯示

## 共用組件

`SiteHeader`（雙品牌識別＋文字主選單＋搜尋＋社群）、`SiteFooter`（分類、社群、作者、聯絡、隱私）、`Breadcrumb`、`WorkCard`、`Tag`、`PlatformLinks`、`RelatedWorks`、`Comments`（可插拔第三方）、`ContactForm`（第三方安全提交）。

所有列表只能引用公開資料。UI 不應在每個頁面硬編社群 URL、作者姓名或封面資源，改從同一份設定或作品紀錄讀取。

## 1. `/` 首頁

- 首屏：品牌與作者署名、清楚主標、互動故事書、五大入口、靜態文字導覽備援。
- 往下：最新文章、主題、精選作品、最新 Podcast、出版書架、作者簡介、來信入口。
- 卡片上至少顯示：分類、正式標題、簡介、封面或替代插畫、公開日期（若適用）。
- 最新文章只取 `publication_status=published`、`published_at <= now`（UTC 或台灣時區一致處理）；任何尚未核准文件不可存在公開 repo，不能只靠 UI 篩選。

## 2. `/articles/` 探索文章

- 全文搜尋（標題、摘要、作者核准的內容全文或編入索引的正文）、內容類型與主題標籤篩選、依日期排序。
- 篩選結果有明顯狀態提示；沒有結果時提供清除篩選。
- 主題數量會成長，但固定分類不應任意增加以免混亂。受控標籤必須有 canonical slug／顯示名稱。

## 3. `/articles/{slug}/` 文章詳頁

### 共通資訊
- 類型、主題、標題、副標、作者公開署名、公開日期與更新日期（若有）、閱讀時間估計、封面插畫、連續正文。
- 文章正文只讀取「IG／Vocus 共用書面定稿」，可提供段落小標、註解與引文排版；不得自行添加評論／人生結論。
- 依作品資料決定顯示：對應 Spotify 單集播放器或連結、Instagram 圖卡貼文連結、Vocus 文章連結、參考資料、相關作品、公開留言。
- M5-A 決策：不開發 IG 圖卡閱讀器，僅提供正式連結；網站維持完整文章。Podcast 封面亦不應隨意重用文章主圖。
- 外連未提供時隱藏該項，而非產生空白或假按鈕。
- SEO：OG 圖片、文章結構化資料、canonical URL、標題摘要；若與 Vocus 出現相同正文，canonical／搜尋策略須經作者選定，不擅自跨網域指定 canonical。

### 長篇／深度文章
- 更沉浸的主圖、較寬開場留白、可選目錄、長文易讀欄寬。
- 內頁圖片需有敘事或知識功能，不能機械重複封面圖。

### 凡思維
- 較短 Hero、快速進入正文；研究來源區可清楚列出論文、年份、DOI／URL、延伸資料。
- 專業內容維持原稿已確認的事實與表達，不自動插入防禦性說教或外部推測。

## 4. `/podcast/` 與 `/podcast/{episode_slug}/`

- `/podcast/`：節目品牌、節目介紹、最近單集與歷史列表、搜尋／主題過濾、Spotify 節目外連。
- 單集頁：正式 Podcast 標題（可與文章標題不同）、單集介紹、封面、發布時間、Spotify 官方播放器、關聯文章、延伸閱讀。
- 沒有對應文章也可展示單集；沒有有效播放器 URL 時顯示外連或可讀單集介紹，不憑空組裝 embed。
- 完整 Podcast 逐字稿**預設不公開**；逐字稿有獨立批准公開欄位時才顯示。
- 單集 RSS 發布後可自動進列表；與文章關聯依明確映射檔或確認過的 GUID，不猜測異名配對。

## 5. `/works/` 出版書架

- 先以收藏書架式展示已出版書籍與原創作品。依狀態（已出版／短篇小說／系列創作）篩選。
- 對每本書使用真實、獲准的封面，書本 hover 小幅向外抽出；手機版點擊開啟。
- 作品卡不得把未出版計畫偽裝成已出版書籍；必須使用 author-confirmed `publication_status`，並另存 `work_form` 與 `series`。

## 6. `/works/{slug}/` 與 `/works/{slug}/world/`

- 作品資訊：正式書名、類型、作者、出版狀態、出版社與出版年份（如核准）、真實書封、簡介、系列閱讀順序、可公開試讀、出版／購書／其他既有官網連結。
- 每本書可有獨立配色／象徵背景，但保留核心導覽與閱讀標準，避免每篇變獨立難維護網站。
- 僅作品世界資料已公開且作者核准時，提供 `/world/` 子頁；支持人物、地點、事件、番外，但不得自動發明世界觀。
- 作品與文章互相推薦可使用 `related_work_ids`，例如關於 AI 的文章連到作者既有 AI 小說；不能機械套用主題而製造錯誤關聯。

## 7. `/about/` 作者介紹

- 首頁與作者頁應有雙品牌一致性；作者頁放已核准的正式署名、照片（如提供）、簡介、醫學／寫作背景、出版書籍、創作年表、Podcast 與合作入口。
- 不從其他來源擅自拼接個人故事、臨床案例或敏感背景。若未提供照片，展示適當的文學／工作桌意象，不生成冒充本人照片。
- 年表只保留核准年份、事件與素材；資料缺失時以乾淨列表替代、不補造年份。

## 8. `/contact/` 私人聯絡

- 至少提供「讀者來信／合作邀約」分類、姓名或暱稱（可匿名視服務條件）、回覆 Email、訊息、必要的隱私說明、成功／失敗提示。
- 使用可防垃圾訊息的外部表單服務／安全後端，不可用純前端收件後直接送往個人信箱、公開個人信箱或 API 密鑰。
- 不收集與目的無關的敏感個資；禁止對外顯示實際送達的郵件內容。

## 9. 留言系統

- 出現在文章與出版作品頁，支援公開留言、作者回覆、管理者審核／刪除／封鎖、垃圾訊息防護。
- 不能把 Giscus（需 GitHub OAuth）當成**唯一**讀者留言方式；如果最後選擇 Giscus，必須另提供低門檻討論通道，且應由作者明確接受限制。
- 建議 Codex 在 M5 比較訪客可留言、中文顯示、審核、資料可匯出、成本與第三方追蹤的方案，提出推薦供作者確認。服務未設定前展示「留言功能準備中」或引導 IG 討論，**不得把假表單宣稱可送達**。

## 10. 錯誤與空狀態

- 未找到文章：404 與搜尋／回列表。
- 作品無 Podcast：隱藏播放元件。
- RSS 暫時失敗：保持上次成功公開的網站，不清空所有單集；提供人工重跑機制。
- 圖片缺失：適當占位及 ALT，不生成假封面。
- 搜尋無結果：可回所有作品，不顯示空白。
- 第三方留言／表單失效：告知讀者目前不可用，不吞掉訊息。
