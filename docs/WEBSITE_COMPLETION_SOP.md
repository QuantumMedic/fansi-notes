## Codex 最省額度執行規則

1. 每次只讀：AGENTS.md、docs/CURRENT_STATE.md、本 SOP、**當次要改的檔案與對應驗證紀錄**。歷史長報告、所有 docs、48 篇正文、所有 Canva 設計**不准預先全讀**；只有實際所需且缺證據才擴大查找。
2. 每次只執行作者指定的**一個階段／一個 PR 範圍**。先確認分支最新 SHA；本機 Codex 需先同步 GitHub 遠端更新。已批准的原文、分類、插畫、Canva 人工調整不重做。若需要權限、真實新資料或作者價值判斷，集中一次交作者；其他可確定項目繼續。
3. **測試最小化**：開發中先跑受影響的精準測試；PR 收尾跑一次 check＋build＋相關批次測試，GitHub CI 由 push 自動驗證。內容與視覺修改做有代表性的桌機手機抽查；純文件或索引清單修改不要做截圖或全面瀏覽器巡檢。M5-F 才做一次全站回歸。若新缺陷確實改動已驗收範圍，只重測受影響的部分。
4. 一份中心進度表（可放 docs/CURRENT_STATE.md 的最上方）：每階段「待開始／執行中／阻擋／待作者驗收／已驗收」；只有一份未完成例外清單，不在文件後方持續堆積會誤導 Codex 的舊狀態。更新狀態採短摘要，不反覆重寫完整歷史。
5. 輕度：查表、精確對應、批次 metadata／單純圖檔連結；中度：跨資料來源配對邏輯、複雜元件、反覆除錯、全站驗收與部署。高強度不作為預設。PR 提交必須列「實際完成、未完成及原因、測試範圍、未核准事項」，不要以 CI 通過宣稱內容全部完成。
