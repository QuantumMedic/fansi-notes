# 06｜Codex 開發計畫、分段 PR 與驗收

**開發原則：** 先做可用的網站，再逐步提升互動；每個里程碑都要可預覽、可回退、可驗收。不要一次把所有模組寫完才讓作者看到。

## M0｜啟動與技術核對（先做）

- 確認 GitHub repo `QuantumMedic/fansi-notes` 目前僅基本 README；保留現有內容，不碰 `reincarnation-simulator`。
- 讀完本交接包，列出已確認／待作者提供的資產，提出分階段 PR 計畫。
- 確認 Astro 最新相容版本、Node 與套件管理工具；設定專案型 Pages `site` 和 `/fansi-notes/` base。
- 最初只能使用**虛構測試文章與占位插畫**，不匯入五篇未公開作品。

**驗收：** 提供架構概述、預計 PR、部署風險與未知項清單；沒有任何網站公開。

## M1｜設計系統與網站骨架

- Astro 頁面路由與共用 Header/Footer、搜尋入口、分類、作者與出版頁殼層、404。
- 繁體中文排版、暫定品牌色 Token、可替換字體、全站手機導覽。
- 文章資料集合的 schema 與基礎 TypeScript 型別，僅 synthetic data。
- CI：建置、型別、schema 與基本頁面測試；部署可在**獲作者同意後**設為 GitHub Pages 預覽。

**驗收：** 所有頁面路由正常、導覽可操作、手機無溢出、未出現真實未發布作品內容。

## M2｜互動故事書首頁

- 首屏的完整場景占位稿：展開的書、五個互動場景，同一個美術空間。
- 小幅視差、hover/focus 預覽、鍵盤與觸控替代、reduced motion、靜態失敗備援。
- 主畫面下方依編輯雜誌格式接續最新、精選、Podcast、出版與作者區塊。
- 插畫尚未定版時，用清楚標示的分層占位素材演示，不製作不受作者認可的永久 AI 主圖。

**驗收：** 桌機滑鼠、鍵盤、手機及 reduced-motion 四種情境的實際截圖或短影片；不強制捲動、不發聲、不因動畫阻擋連結。

## M3｜文章、分類、Podcast 與同步

- 深度文章／凡思維兩種版型，共用真實資料模型與 metadata schema。
- 最新文章、所有文章、主題頁、搜尋、相關作品；標籤改一次自動更新相關列表。
- Podcast RSS（含 timeout 與 failure fallback）、獨立單集頁、Spotify Embeds 與 `guid → work_id` 配對表。
- 外部 IG／Vocus／Spotify URL 的統一儲存與條件顯示；異名標題不誤配。
- 建立一個可閱讀的「如何新增一篇文章」工作流程；作者可以透過 ChatGPT GitHub 連接器／Codex 同步經核准的文章，不手動複製多處。

**驗收：** 使用**合成測試文章**成功新增、重命名、改分類、改標籤、補 Instagram URL、補 Vocus URL、RSS 模擬新集數、手動配對；各頁正確更新且無錯誤重複。

## M4｜書架、獨立作品世界、作者頁

- 收藏書架互動，真實書封未提供時用占位圖；書籍／作品詳頁、系列順序、試讀可用性、外部購書連結。
- 作品個性化場景樣式，保留全站 UI 一致性；沒有世界觀資料不生成空世界頁。
- 作者簡介、創作年表、社群與合作導覽；只使用作者核准文字與圖片。

**驗收：** 可加入合成一本書，更新書封／購書 URL，一次更新所有相關展示；無假的出版年份、購書網址、作者經歷。

## M5｜讀者交流、公開部署與正式 QA

- 留言方案比較，由作者批准服務、登入門檻、費用；作者回覆、審核、垃圾訊息防護。
- 私人聯絡表單：送達、錯誤處理、最少個資、隱私文案、合作分類。
- GitHub Pages、網頁 SEO、搜尋、行動端和輔助科技測試。
- 作者核准首批**已公開**內容後再上線，建立維護流程與回滾說明。

**驗收：** 真實留言可送出／審核／刪除／作者回覆；私訊可實際送達；網站所有主要頁面可用且公開內容經批准；部署流程不洩漏私人資料。

## M6｜私人 Fansi Studio 整合（後續階段，勿搶跑）

- 研究私人狀態卡與網站作品的對應、私人稿件保存、預排發布、Meta API 自動發現 IG 等。
- **未經作者另外確認不可直接建立登入後台、私人資料庫或社群自動代發。**

## 橫向測試矩陣

| 情境 | 預期結果 |
|---|---|
| 建立一篇合成凡思維文章 | `/articles/`、凡思維分類與對應主題列表自動顯示 |
| 建立合成深度文章 | 使用較沉浸模板，完整文字可選取 |
| 更改文章標籤 | 不用手動改每個分類頁，建站後自動更新 |
| 修改 slug | 舊 URL 有明確 redirect／兼容策略，不變 404 |
| 同一作品的 Podcast 標題不同 | 依 GUID 對應 `work_id`，不靠標題猜測 |
| RSS 有新集數，未配對文章 | 單集可在 Podcast 列表，文章尚不顯示錯誤播放器 |
| RSS 暫時 500／超時 | 網站保有最近一次成功發布版本，排程失敗可重跑 |
| 已核准文章但 IG URL 未填 | 文章可讀，但無假 IG 連結 |
| 已公布 IG URL | 只更新一筆 metadata，文章頁顯示正確 IG 入口 |
| 未核准文章／書封 | 不能存在 public repo，也不能進索引或可存取 URL |
| 首頁關閉動態、使用鍵盤 | 五區可聚焦、可 Enter 點擊、文案可看見 |
| 手機窄螢幕 | 封面、書架、目錄、表單不溢出或互相遮蓋 |
| 公開文章留言 | 訪客不需 GitHub 帳號（依所選方案），作者能管理 |
| 表單輸入無效／服務失效 | 讀者收到可理解錯誤，不假稱傳送成功 |
| 測試 RSS 帶 HTML／惡意連結 | 不執行 HTML，不產生 XSS、JS URI |

## 交付物與回報格式

每個 PR 包含：本 PR 的功能範圍、對應規格、畫面截圖／影片、桌機與手機驗證、測試結果、未解決問題、回退方式。除非作者明確授權，不自動 merge PR、不對外公開真實作品。

完成 M3 後提供一頁「非工程師每週怎麼更新網站」的操作說明，須能用 **《三個傻瓜》的合成資料**示範新增作品、補 IG URL 和關聯 Podcast，但不得在公開程式庫放入實際未發表全文。
