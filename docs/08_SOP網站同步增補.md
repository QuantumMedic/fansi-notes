# 08｜《凡思筆記／凡思聲》原 SOP v4.0 的網站增補條款

> 本條款新增於原 SOP 的「H 最終交付」之後。**不更動原本 Podcast 母稿、IG／Vocus 共用母稿、Canva 與作者審核的順序。**

## I｜作品網站同步（只有當次要求網站同步才執行）

1. **辨識作品身分**：沿用既有 `work_id`，確認正式標題、`content_type`、主題標籤、相關作品與書面母稿版本。
2. **確認網站公開權限**：作者明確說「可同步並公開網站」後，才可把核准全文寫入公開 GitHub repo；「本篇定稿」或「SOP 完成」本身並非公開授權。
3. **產生網站單篇記錄**：沿用已核准 IG／Vocus 書面母稿，生成網站正文與必要 metadata，不重新撰寫文章、不重複上傳同一全文到多個列表。
4. **同步至 GitHub**：用已連接的 GitHub 工具或 Codex 建立／更新 `fansi-notes` 的作品資料，經作者確認差異後合併；GitHub Actions 自動建置、更新最新文章／分類／搜尋與相關作品。
5. **處理外部連結**：IG、Vocus 作者自行發布，提供公開 URL 各一次即可；Spotify RSS 可自動發現新集數，與文章配對以 GUID／作者確認的映射為準，**不自行代發**。
6. **最後驗收**：網站頁面、分類、摘要、插畫、外連、Podcast 播放器／連結皆檢查；更新單篇狀態卡 `website_status`, `website_url`, `approved_revision`, `last_synced_at`。

## 本網站同步階段的四句操作語言

- **「這篇先定稿，不公開網站」**：維持私人內容，絕不寫入公開 GitHub。
- **「這篇現在同步並公開網站」**：執行權限與稿件檢查，建立 GitHub 更新並部署。
- **「這篇 IG／Vocus 已發布，這是連結：…」**：只更新該作品平台 URL，不改動文章正文。
- **「幫我核對網站和 Canva／Podcast 的版本」**：只查核與回報差異；除非授權，不自行覆寫正式文字。

## 跨對話的實際限制

每次 SOP 完成時，ChatGPT 對話**不會自行發訊息到 GitHub**。需要在當次會話做一次 GitHub 寫入／Codex 提交，或由未來另外建立、經授權的私有 Fansi Studio 服務觸發。任何沒有工具實際完成的同步，不應宣稱已更新網站。
