# 05｜技術架構、部署、安全與第三方整合

> **技術方向為 Codex 的實作預設，不是作者已選定每項第三方服務商。** 先建立可運行、可維護、可審核的靜態網站，再決定需要伺服器的留言、聯絡與私有管理介面。

## 1. 建議技術選型

- **網站框架**：Astro，內容中心使用 Content Collections + schema 驗證（官方文件 https://docs.astro.build/zh-tw/guides/content-collections/ ）。
- **樣式與互動**：可維護的 CSS variables + Astro 元件，輕量瀏覽器 JS／SVG／分層插畫；非必要勿引入龐大前端框架與 WebGL。
- **內容格式**：Markdown／MDX（正式書面母稿）配合結構化 frontmatter／JSON／YAML（作品與跨平台 metadata）；需明確區分內容、媒介與作者資料。
- **版本**：GitHub `QuantumMedic/fansi-notes`；代碼與公開文章均可版本化；私人備稿不得存於此公開 repo。
- **部署**：先用 GitHub Pages + GitHub Actions。專案型 Pages 預設會在 `https://QuantumMedic.github.io/fansi-notes/` 路徑下服務，Astro 必須設定 `site` 與 `base`，資產連結不能直接假設根路徑 `/`。
- **網域**：第一版不需自訂網域；未來若購買，可設定 DNS／canonical／redirect。
- **Podcast**：Spotify 公開 RSS 抓取已發布集數，官方 Spotify Embed 播放；不自建音檔主機。

## 2. 建議開發資料夾（Codex 可依實作需要微調，需說明理由）

```text
fansi-notes/
├── README.md
├── AGENTS.md                       # 專案開發約束、交付規範
├── docs/                           # 本交接文件
├── public/
│   └── assets/                     # 只有核准公開的圖與書封
├── src/
│   ├── components/                 # Header, Footer, Cards, Player, Comments
│   ├── layouts/                    # Main, Article, Book, Podcast
│   ├── pages/                      # 靜態路由與動態預建路由
│   ├── styles/                     # Design tokens, typography, animation
│   ├── data/
│   │   ├── site-config.*           # 公開社群網址、作者公開署名
│   │   ├── topics.*                # 受控標籤表
│   │   └── podcast-work-map.*      # 人工核准 GUID → work_id 對照
│   └── content/
│       ├── articles/               # 僅作者核准公開的正文
│       ├── books/                  # 僅核准公開的書籍資料
│       └── fiction/                # 僅核准公開的小說資料
├── scripts/                        # RSS 擷取、schema/連結驗證、內容匯入
├── tests/                          # 自動測試；只使用合成假資料
└── .github/workflows/
```

上述目錄是**實作藍圖**；本交接包不需要先建立這些程式檔。

## 3. GitHub Pages 與發布安全

- `main` 合併前執行 typecheck、內容 schema、連結與圖片檢查，通過才部署。
- `main` 只讀取核准公開的內容。避免包含已核准但尚未發布的全文；Git 公開歷史無法靠刪除前端頁面補救。
- 五篇已完成但尚未發表的作品僅當**驗收用例名稱**。初期開發用合成測試資料；公開網站示意不能顯示未授權原文。
- 若要提前排程含全文的未來文章，應新增**私人來源**，由發佈程序在指定時間轉送核准內容；不把私人內容推到公開 repo 的任何分支。
- GitHub Pages 是公開網站，不提供自有動態資料庫；留言、表單需外部合規服務或另設後端。

## 4. RSS 同步設計

- 建站時抓取公開 RSS，轉成必要公開資料，驗證 `guid`、`title`、`pubDate`、官方 URL；設定合理 timeout、重試與網路失敗 fallback。
- RSS 若包含公開聯絡 email 等敏感欄位，**不可將整份原始 feed 提交 repo**；僅使用公開展示必要欄位。
- 可由 schedule 每日觸發、提供 workflow_dispatch 手動刷新；GitHub 官方明確說明排程可能延遲或被跳過，**不能保證準時到秒**（https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows）。
- RSS 來源若暫時失效，不能產生空白 Podcast 頁並部署；記錄失敗、維持上一次成功的公開網站。
- RSS 單集→文章配對使用經作者確認的 `episode_guid` 映射；不存在時不自動誤連，保留 Podcast 獨立單集列表。

## 5. 留言與聯絡表單（需作者決定服務）

### 留言

- 需求：中文、低門檻讀者、可匿名／訪客或常見登入、作者回覆、審核與反垃圾訊息、資料可管理、適配主題。
- **Giscus** 雖然可以免費使用 GitHub Discussions，但訪客留言需要 GitHub 身分授權（https://github.com/giscus/giscus）；**不符合單一主要方案的低門檻目標**。
- 可評估 Hyvor Talk 等提供訪客留言及審核的外部服務（https://hyvor.com/talk/docs），涉及訂閱費用須先讓作者確認；不硬綁未核准服務或付款帳號。
- **Cusdis 現已宣布 deprecated**，不適合當新站預設依賴（https://github.com/djyde/cusdis）。
- v1 可先有完整 UI／介面適配與「功能準備中」狀態，但正式對外宣稱可留言前，必須實際測試送出、回覆、審核與通知。

### 聯絡

- 靜態網站可使用 Formspree 類服務（Cloudflare 有公開靜態表單整合教學：https://developers.cloudflare.com/pages/tutorials/add-an-html-form-with-formspree/）。
- 必須由作者持有該服務帳號；在實作設定時提供安全的 endpoint，測試送達、垃圾訊息、失敗重試、隱私告知。
- 不將目的地私人 Email、private API key、收件內容或隱私資料寫進公開 GitHub 或前端 bundle。

## 6. SEO、效能與可用性

- 全站 `lang=zh-TW`、自動 sitemap、robots、每頁 title／description／OG image；發布日期與修改日期正確。
- `Article`／`Book`／`PodcastEpisode` schema.org 結構化資料依實際內容使用，**不可造假出版資訊與播客連結**。
- 文字可在無 JS 下閱讀；互動失效也可用導覽；尊重 reduced motion、鍵盤、focus、aria、ALT。
- Hero 優先以靜態底圖＋少量分層，避免首屏引入昂貴 WebGL。延遲載入下方圖片、使用響應式尺寸、圖像壓縮，測試行動裝置。
- 目標：Lighthouse 行動裝置 accessibility 90+、performance 80+ 作為初版合理門檻（需提供測試環境與結果）；核心無橫向捲動、文字不裁切、關鍵選單可點。
- 外部 Spotify／社群嵌入延遲載入，必須提供不載入 iframe 也可用的外連；載入前依實際第三方隱私政策告知。

## 7. 安全與維運

- GitHub Actions 權限最小化，定期檢查依賴；不允許未經授權外部內容觸發任意網路下載或寫入檔案。
- RSS 與留言為不受信任輸入，必須跳脫 HTML、拒絕 XSS、限制外部 URL scheme、處理錯誤標題與內容。
- 需要監測建置失敗與回滾，部署前保有 CI 驗收與至少一個可回復版本。
- 維護者操作說明包含：新增文章、修正分類、補 IG／Vocus URL、配對 Podcast、重新抓取 RSS、撤下文章、更新 book metadata。
